# 610.57.04 full-stack release validation — 2026-08-08

## Scope and result

This record closes the candidate `nvidia-drm.ko` load limitation documented in
[`pcie-p2p-policy-2026-08-07.md`](pcie-p2p-policy-2026-08-07.md). The source
under test was commit `9c1898d0ccf7e65b06c9ba2c7023f5a63a51264b` on
`release/610.57.04-p2p-dmabuf`.

The earlier unresolved reference to
`drm_fbdev_ttm_driver_fbdev_probe` was not a driver-source, conftest, kernel
header, or symbol-version defect. It was caused by raw `insmod`, which does not
load dependencies. The symbol is provided by the modular
`drm_ttm_helper.ko`, and `nvidia-drm.ko` correctly declares
`drm_ttm_helper` as a dependency. The separate modeset failure had the same
integration cause: raw `insmod` did not load the declared `video` dependency.
Dependency-aware `modprobe` loaded both dependencies and the complete candidate
stack successfully. No source change was required.

## Symbol and conftest diagnosis

The build/runtime symbol matrix was `present / present`:

```text
$ grep -w drm_fbdev_ttm_driver_fbdev_probe \
    /lib/modules/7.0.0-29-generic/build/Module.symvers
0x687ea481 drm_fbdev_ttm_driver_fbdev_probe \
    drivers/gpu/drm/drm_ttm_helper EXPORT_SYMBOL

$ grep -w drm_fbdev_ttm_driver_fbdev_probe /proc/kallsyms
0000000000000000 T drm_fbdev_ttm_driver_fbdev_probe [drm_ttm_helper]

$ modprobe --dump-modversions kernel-open/nvidia-drm.ko | \
    grep drm_fbdev_ttm_driver_fbdev_probe
0x687ea481 drm_fbdev_ttm_driver_fbdev_probe
```

The official and candidate `nvidia-drm.ko` modules use the same `0x687ea481`
CRC. `nm -u` and `readelf -Ws` show the expected undefined reference in the
candidate, to be resolved by the provider module at load time.

The clean conftest selected `NV_DRM_CLIENT_SETUP_PRESENT`, rejected the older
`NV_DRM_FBDEV_TTM_SETUP_PRESENT`, and detected the TTM fbdev header. With
`CONFIG_DRM_TTM_HELPER=m`, `nvidia-drm-conftest.h` enables the client fbdev
path. `nvidia-drm-drv.c` uses `DRM_FBDEV_TTM_DRIVER_OPS`; the matching kernel
header expands that macro to a `.fbdev_probe` assignment referencing
`drm_fbdev_ttm_driver_fbdev_probe`. This accurately describes the running
kernel.

Dependency metadata then identifies the integration requirement:

```text
nvidia-modeset.ko: video,nvidia
nvidia-drm.ko:     nvidia-modeset,drm_ttm_helper
nvidia-uvm.ko:     nvidia
nvidia-peermem.ko: nvidia,ib_uverbs
```

`modprobe --show-depends nvidia_drm` included `video.ko`, `ttm.ko`, and
`drm_ttm_helper.ko` before the NVIDIA modeset and DRM modules.

`/lib/modules/7.0.0-29-generic/updates/local` directory, followed by
`depmod -a`. With no device users and no active display manager, the candidate
stack was unloaded and loaded with dependency-aware commands.

`nvidia-smi` and `nvidia-smi -q` completed against both GPUs. DRM initialized

The candidate stack completed repeated full unload/reload cycles, including a
final explicit unload and reload of all five modules. Both GPUs remained
queryable afterward.

## Kernel health and rollback

The candidate interval was bounded by a kernel marker and contained six full
unload/reload cycles. It had no Xid, NVRM assertion, MMU or IOMMU fault, AER
fault, kernel warning/oops, BUG, panic, hung task, call trace, IOVA teardown
warning, unknown symbol, or module-version disagreement. An NVRM assertion at
09:52 in the same boot predates the 12:50 validation marker and was not part of
this bounded run.

After validation, the five controlled `/updates/local` candidate copies were
removed, `depmod -a` was rerun, and the untouched official 610.57.04 modules
from `/updates/dkms` were reloaded. The official srcversions were restored:
