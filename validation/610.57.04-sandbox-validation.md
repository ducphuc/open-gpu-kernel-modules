# 610.57.04 clean-port sandbox validation

Date: 2026-08-07

## Scope

This record covers the clean consumer GB20x BAR1 and non-coherent DMA-BUF GDR
port based on the official `610.57.04` commit
`e4a5faa2567f28c8eabe0ebb6422b6d0abcf37eb`.

The validation was performed without installing or loading modules and without
using `nvidia-smi`. Those operations require a suitable GPU host and are not
valid sandbox substitutes.

## Results

- `make -C tests check`: passed with GCC. All three policy programs were built
  with `-std=c11 -Wall -Wextra -Werror` and passed.
- `make -B -C tests CC=clang check`: passed with Clang under the same warning
  policy.
- `make modules -j4`: passed against
  `/usr/src/linux-headers-7.0.0-29-generic`. It built `nvidia.ko`,
  `nvidia-uvm.ko`, `nvidia-modeset.ko`, `nvidia-drm.ko`, and
  `nvidia-peermem.ko`. The build emitted the existing objtool mitigation
  warnings and skipped BTF generation because `vmlinux` was unavailable; it
  completed successfully.
- The three rejected commits are not ancestors of the clean branch:
  `9fb650447c7beb2083822268a4697c0fed109d31`,
  `52670f7fd6a7a214be6fad6d8d90854e8b7d8470`, and
  `31906f937249a4cd68b0fb7eaef823058edf4a46`.
- `install.sh` is absent.
- Generated HAL sources are identical to the official `610.57.04` base.
- The old global BIF, GP100 routing, and IOVA-bypass files are identical to the
  official base.
- The official `610.57.04` DMA-BUF partial-refcount unwind remains present.
- The clean port does not contain the rejected hugepage experiment.

## Hardware validation still required

On a matching 610.57.04 GPU host, rerun the documented BAR1 boundary and
same-host DMA-BUF GDR reproduction plans. Confirm PCI topology, IOMMU identity
domain, BAR1 coverage, registry opt-in, DMA counters, CUDA transfers, and NCCL
transport selection. Do not treat the historical 610.43 results as 610.57.04
passes.
